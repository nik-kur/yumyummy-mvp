## Решения

- **Всё в коде (React Native):** онбординг 1–16, пейвол 17–19, оффер после отмены 20, preview mode и Last offer 21, экраны после покупки 22–25.
- **Adapty = пульт.** Какой вариант экрана показать, включён ли экран, все тексты, цифры, отзывы и фото приходят из remote config плейсментов Adapty. A/B тесты создаются в дашборде Adapty. Релиз нужен только для нового типа экрана или нового взаимодействия.
- **Слоты Adapty.** В пяти местах конфиг может вместо нашего экрана открыть флоу Adapty: welcome, отзывы (16), пейвол (17–19), оффер после отмены (20), Last offer (21). Так любой из этих экранов можно потом пересобрать в Flow Builder и тестировать без релиза.
- **Один билд на всё**, включая отложенные правки 1.0.11 (оффер после отмены на кодовом пейволе, `adaptyErrorContext`, см. memory). Код можно делать по шагам, на ревью уходит одна сборка.
- **«50% OFF» на 20 и 21 оставляем как есть** (решение Никиты 15 октября; риск по исходной цене озвучен).
- **Обновление 18 окт:** отзывы и фото до/после — реальные клиенты с согласием (Никита: пометки «SYNTHETIC / демо» в таблице аналитика — остаток шаблона); экран 16 включён для всех через Adapty. Ниже — исходная запись от 15 окт.
- **Отзывы и фото до/после сейчас демо** (вымышленные люди из таблицы помощника, статус «SYNTHETIC — INTERNAL DESIGN TEST ONLY»). Экран 16 скрывается конфигом. До показа реальным пользователям заменить на реальные отзывы с согласием (британские правила о фейковых отзывах). Отзыв в карточке лоадера 14 тоже демо, а лоадер видят все: по умолчанию карточку не показываем, пока нет реальных (следствие этого правила, 15 октября).
- **Пейвол:** все варианты фото в коде. Никита показывает по одному и переключает удалённо, без билда. В код идёт и версия как у Cal AI (тест P1, решение 15 октября): экран 1 с демо-видео в айфоне (три ролика: фото, текст, голос) → напоминание 18 → светлые планы с таймлайном. Ролики лежат в бандле, поэтому задержки старта, как у HLS-видео во флоу Adapty, нет.
- **ATT:** остаётся над лоадером. Ожидание AppsFlyer (`waitForATTUserAuthorization`) поднять с 60 до 180 с, иначе согласие, данное на лоадере (~2 мин), не привяжется к установке. Сам AppsFlyer описывает этот случай: промпт после ~2-минутного туториала → 120 с ([integrate-ios-sdk](https://dev.appsflyer.com/hc/docs/integrate-ios-sdk)). Пока таймер идёт, SDK держит launch и события в памяти ([207032066](https://support.appsflyer.com/hc/en-us/articles/207032066)). Что происходит, если приложение закрыли до промпта, в документации нет: проверить на устройстве с `isDebug`. Вариант «ATT на welcome» (тест O6) включается конфигом, таймер 180 с подходит обоим.

## Конфиг

Каждый вариант (арм) в Adapty = флоу с remote config. Нативный арм = флоу-«носитель» конфига (один пустой экран), как сейчас контроль `pw_main` 482e6945 с `use_native`. Во всех армах оставить `use_native: true`: билды ≤1.0.10 читают только его и показывают старый нативный онбординг.

**`onb_main`: переключатели тестов онбординга.** Приложение читает его на старте (`getFlow`, таймаут ~1 с). Не успело → значения по умолчанию из кода (контроль). Черновик ключей:

```json
{
  "use_native": true,
  "onboarding": "v3",
  "welcome": { "render": "native", "variant": "A", "headline": "Calorie tracking made easy", "subline": null },
  "features": "screen",
  "social_proof": { "render": "native", "show": true, "hero": "before_after" },
  "plan": "chart",
  "att": "loader",
  "ask_name": false,
  "free_first_log": true,
  "after_cancel_offer": true,
  "tutorial": true
}
```

Значения: `onboarding` v3 | v1 (текущий онбординг, контроль для T0); `welcome.variant` A–D (O3); `features` screen | try_it | off (O1, O2); `social_proof.hero` before_after | text (O4); `plan` chart | ahead (O7); `att` loader | welcome (O6); `ask_name` (O5); `free_first_log` (PM2); `after_cancel_offer` (C5). `render: "flow"` = открыть слот Adapty.

**`onb_content`: контент, общий для всех армов** (без A/B, один флоу-носитель). Отзывы по целям lose / gain / maintain / track: текст, имя, город, подпись, ссылки на фото до/после. Цифры (`rating` "5.0", `users` "12,000+"). Тексты по ключу, например `reflect.gain.title`. По умолчанию везде тексты из дизайна. Фото по ссылкам: лежат на нашем сервере, приложение скачивает их на старте (экран 16 наступает через ~2 минуты). Welcome грузит фото только из бандла.

**`pw_main`, `pw_after_cancel`: пейвол и офферы.** В remote config арма: `{"use_native": true, "render": "native", "variant": "b3_joe", "copy": {…}}` → наш экран. Конфига нет или `render: "flow"` → экраны самого флоу. Варианты в коде:
- `b3_joe` (контроль), `b3_home`, `b3_office`, `b3_wide`: B1 с заголовком из плана → B2 с напоминанием и запросом пушей → B3 с фото;
- `p1_photo`, `p1_text`, `p1_voice`: экран 1 с видео в айфоне → B2 с напоминанием и пушами → светлые планы (`PW_P1_plans`);
- оффер `costa` (контроль), `closeup`.

**Last offer** = повторное открытие `pw_after_cancel`: Adapty держит человека в том же арме, поэтому фото совпадёт с экраном 20 само. Проверить на устройстве.

| Место | Плейсмент | Как приложение продолжает |
|---|---|---|

Сохранить существующий контракт `mobile/src/billing/flowBridge.ts`: custom actions, custom tags (HERO_LINE и др. — inline-узлы `variable`, не текст `<TAG/>`), запрос разрешений `tracking` / `push`.

## Пейвол в коде: метрики Adapty

- Продукты брать у флоу арма: `adapty.getPaywallProducts(flow)` → `adapty.makePurchase(product)`. Показ логировать: `adapty.logShowFlow(flow)` (оба метода есть в react-native-adapty 4.2.1). Тогда кодовые и билдерные армы сравниваются в одном A/B тесте Adapty. Сейчас кодовый пейвол берёт продукты с legacy-плейсмента `main`, поэтому его покупки не попадают в метрики `pw_main`; это исправить.
- Тесты цен, планов и триала (P5–P7) делаются продуктами на флоу арма, без релиза, и для кодового пейвола тоже. Для этого кодовый пейвол рисует столько карточек планов (1–3), сколько продуктов пришло с флоу.

## Экран 0: заставка (решение 15 октября)

- Один вариант, без теста. Показываем при первом запуске, пока грузится конфиг Adapty (`getFlow(onb_main)`): минимум 1,4 с, чтобы вступление прошло целиком, максимум 3 с, потом Welcome. Если конфиг пришёл раньше, после вступления сразу идём дальше. При повторных запусках экрана 0 нет.
- Сюжет «иконка оживает»:
  - фон экрана терракотовый (`#B85A3A`, правка Никиты 15 октября); нативный launch screen показывает кремовую «Y» в центре, как на иконке;
  - 0,15–0,42 с: «Y» сжимается и лопается, открывается бежевый круг (`#F7F1E6`), в него выпрыгивает персик с сердцем (`mascot_heart`);
  - 0,6–0,7 с: приземление со сжатием;
  - 0,85 и 0,98 с: сердце бьётся дважды, расходятся два кремовых круга;
  - 0,7–1,3 с: по буквам проявляется кремовое «YumYummy».

  Если конфиг грузится дольше, персик спокойно «дышит» сердцем, уже без хаптики.
- Хаптика (expo-haptics), больше ничего:
  - `impactAsync(Soft)` на 0,42 с, когда лопается иконка;
  - `impactAsync(Light)` на 0,85 с и `impactAsync(Medium)` на 0,98 с — это «тук-тук».
- Нативный launch screen должен совпадать с первым кадром: терракотовый фон и кремовая «Y» в центре. Сейчас в `mobile/app.json` фон `#FAF5EC` и картинка — терракотовый круг с «Y»: поменять фон на терракотовый и картинку на кремовую «Y» без круга (или круг ровно цвета фона). Вызвать `SplashScreen.preventAutoHideAsync()` и `hideAsync()` после первого кадра экрана 0.
- Reduce Motion: без прыжка, сжатия и кругов, только смена «Y» на персика и проявление имени. Хаптика остаётся.
- Анимация на react-native-reanimated (уже в проекте). Дизайн: артборды `V3_Splash` (анимация по кругу) и `V3_Splash_story` (раскадровка с таймингом хаптики).

### Preview mode (вторая волна, тот же билд)

- Весь API требует аккаунт (`get_current_account`), вход происходит после покупки (`save-plan.tsx`), гостевого входа нет. Нужны: анонимный аккаунт на установку (ключ: Adapty profile id или device id), его merge при Sign in with Apple, лимит один AI-лог на установку внутри `account_has_access` и `/agent/run`, защита от реинсталла.
- Порядок: сначала всё остальное, проверка приложения, затем preview mode, сабмит одним билдом.

### Конфиг первого запуска

- Splash держать до ответа `getFlow(onb_main)` до 2–3 с, не 1 с.
- При таймауте: дефолт из кода, в PostHog `config_source: default`; таких людей в T0 не считать контролем.
- Полученный конфиг и `variation_id` сохранять локально и использовать до конца онбординга, чтобы второй запуск не поменял арм.
- `variation_id` писать в person property PostHog в момент назначения; по нему считается T0.
- Fallback-файл Adapty с контрольным конфигом, если SDK v4 поддерживает его для флоу.

### Старые версии приложения

- `use_native: true` во всех армах всех плейсментов.
- Билды ≤1.0.10 при `use_native` уходят на legacy-плейсмент `main` с кодовым S_hero без цены. Переключить remote config `main` на кодовый вариант с карточкой цены, либо сознательно принять.
- Существующие ключи конфига не менять, только добавлять новые: старые парсеры их игнорируют.
- Старые билды оффер после отмены не покажут, это нормально.

### Sandbox-события

- Как есть: Adapty помечает sandbox, исключает его из своей аналитики, но пересылает в интеграции. В PostHog события идут с `environment = Sandbox`. Наш вебхук sandbox уже игнорирует (`app/api/adapty_webhook.py`).
