## Черновик изменений в Adapty (каждое — только с ок Никиты)

### 1. До отправки на ревью: `pw_main` → V3 в коде — сделано 18 окт

Сделано иначе, чем в черновике ниже: флоу `pw_v3_b3_joe` (`b2d3d236`) — копия `pw_welmi` (те же продукты Monthly + Yearly с триалом), remote config `{"render": "native", "variant": "b3_joe", "price_emphasis": "billed", "show_rating": true}` без `use_native`. Так 1.0.11 показывает V3, а ≤ 1.0.10 — экраны Welmi, как до правки (с `use_native` им достался бы старый нативный пейвол). Обе аудитории `pw_main` → этот флоу, A/B не запущен (вариант А).

Черновик (17 окт):

Новый флоу-носитель (существующие не трогаем):

- Имя: `pw_v3_b3_joe`.
- Экраны и продукты: копия флоу `pw_a_native` (Monthly `cf5874b1` + Yearly 49.99 с 3-дневным триалом `7cbbdae3`, те же, что у `pw_welmi`, чтобы сравнение было честным).
- Remote config (`en`):
  ```json
  {"use_native": true, "render": "native", "variant": "b3_joe", "price_emphasis": "billed", "show_rating": true}
  ```
  `use_native` оставляет сборкам ≤ 1.0.10 их старый пейвол на `main`; `render: native` даёт 1.0.11 пейвол V3 (B1 → B2 → B3), сумма списания крупно.

Куда ставить — выбор Никиты в дашборде (A/B тесты CLI не показывает):
- **Вариант А (безопасно для ревью):** на время ревью `pw_main` для всех → `pw_v3_b3_joe`. После одобрения — A/B `pw_v3_b3_joe` против `pw_welmi`.
- **Вариант Б:** сразу A/B, но тогда ревьюер может попасть в `pw_welmi` с крупной ценой за месяц.

Если на `pw_main` сейчас идёт тест — у него нельзя запускать `placements update --audiences` (стирает армы). Менять через дашборд.

## Проверка на телефоне (TestFlight 1.0.11)

Перед началом: удалить YumYummy с телефона. Для покупки нужен sandbox-аккаунт (Настройки → Разработчик → Sandbox-аккаунт; раздел виден только с включённым режимом разработчика). Покупки в TestFlight — sandbox: в 1.0.11 они не уходят ни в AppsFlyer, ни в Meta (событий покупки из приложения больше нет, интеграция Adapty до релиза выключена). Регистрация аккаунта (`af_complete_registration`) из TestFlight в AppsFlyer по-прежнему уходит.

| # | Что сделать | Что должно быть |
|---|---|---|
| 1 | Открыть приложение | Анимированный старт, затем Welcome |
| 2 | Пройти онбординг | Вопросы, «2×», графики; на загрузке плана — запрос ATT |
| 3 | Пейвол | V3: B1 → B2 с запросом уведомлений → тарифы (с 18 окт) |
| 4 | Нажать покупку и отменить окно Apple | Оффер «Last offer» с крестиком справа сверху |
| 5 | Закрыть оффер крестиком | Настоящий Today, подсказка «See how it works» над «+» |
| 6 | «+» → записать еду текстом | Окно согласия на ИИ, затем настоящий поиск: еда с калориями и источником на Today |
| 7 | Ещё раз «+», потом Profile | Каждый раз Last offer; крестик возвращает в приложение |
| 8 | Удалить и снова поставить приложение, пройти онбординг, отменить покупку, закрыть оффер | Today без подсказки; «+» сразу Last offer (бесплатная запись уже потрачена) |
| 9 | В Last offer купить (sandbox) | «You're all set» → Save plan |
| 10 | Sign in with Apple | Today с туром из 6 шагов; еда из пробного режима на месте |
| 11 | Тур: шаг 3 — записать еду голосом и фото | Настоящий поиск, шаг 4 указывает на новую еду, потом Payoff |
| 12 | Через пару минут | В ленте событий Adapty — sandbox-триал; в AppsFlyer — ничего |

Что проверю сам после этого прогона: события в PostHog (воронка, `offer_context`, `is_first_meal`), ошибки в Sentry (сборка 1.0.11), логи Render (`/auth/install`, слияние аккаунтов, источник IP для лимитов).
